## 2. 已确认产品决策

1. 压缩包只用于管理员批量导入，不向用户分发，也不作为作品可播放或可阅读资源。
2. 支持无密码的 `ZIP` 与 `CBZ`；其它文档保持普通文件处理。
3. 导入完成后，用户仍使用现有图集/漫画阅读器，获取的是 `browse` 图片与缩略图；源图和源压缩包不进入用户 API。
4. 一个作品可同时包含图片和视频；漫画内容单元仍禁止视频。
5. 管理员必须为每个压缩包选择图片排序规则。系统内置规则不能删除；自定义规则允许新增和删除。
6. 压缩包本身不能满足发布校验。只有导入后生成完整 `source / browse / thumbnail` 图片版本、连续页序并由管理员确认可用的内容单元才能发布。

## 4. 数据与接口设计

### 4.1 媒体资源

`media_assets.type` 新增 `archive`，关联字段为：

- `archive_sort_rule_id`：所选排序规则；仅 `archive` 类型可写入。
- `role`：压缩包固定使用 `archive_source`。
- `presentation_scope`：固定为 `protected_content`。
- `status`：关联后为 `pending`，导入 Worker 成功后保留为可追溯源资源。

频道入库元数据包含 `archiveFormat: zip | cbz`、文件名、MIME、大小与 Telegram 文件 ID。

### 4.2 图片排序规则

`archive_sort_rules` 字段：

| 字段              | 含义                                           |
| ----------------- | ---------------------------------------------- |
| `name`            | 管理台显示名称，唯一。                         |
| `kind`            | `natural`、`numeric`、`chapter_page`、`path`。 |
| `file_pattern`    | 可选图片路径过滤正则。                         |
| `chapter_pattern` | 可选章节捕获正则。                             |
| `page_pattern`    | 可选页码捕获正则。                             |
| `direction`       | `asc` 或 `desc`。                              |
| `priority`        | 展示与默认选择排序。                           |
| `enabled`         | 停用规则不能用于新入库。                       |
| `system`          | 系统内置规则标记，禁止删除。                   |

接口：

```text
GET    /api/admin/archive-sort-rules
POST   /api/admin/archive-sort-rules
DELETE /api/admin/archive-sort-rules/:ruleId
```

所有写操作要求 `ingestion.manage` 权限并写入管理员审计日志。

## 5. 排版与排序规则

### 5.1 可接受的目录形态

导入服务只扫描压缩包中的图像文件：`jpg`、`jpeg`、`png`、`webp`、`gif`、`avif`。其它条目默认忽略。

```text
单章节：
  001.jpg
  002.jpg

多章节：
  chapter-01/001.jpg
  chapter-01/002.jpg
  chapter-02/001.jpg

复杂命名：
  第01话/第001页.webp
  第02话/第001页.webp
```

### 5.2 系统内置规则

| 规则       | 使用场景                      | 比较方式                           |
| ---------- | ----------------------------- | ---------------------------------- |
| 自然文件名 | `page-1`、`page-2`、`page-10` | 自然字符串比较。                   |
| 数字序号   | 文件名中带一组或多组数字      | 比较路径中数字序列。               |
| 章节与页码 | 章节目录与页码名称均有数字    | 先章节、后页码、最后自然排序兜底。 |
| 目录路径   | 目录结构已表达章节顺序        | 先目录、后文件名自然排序。         |

### 5.3 自定义规则

管理员可配置三类正则：

```text
图片过滤：       ^第\\d+话/
章节捕获：       第(?<number>\\d+)话
页码捕获：       第(?<number>\\d+)页
```

捕获数字使用命名组 `number` 或第一个捕获组。服务端拒绝回溯引用、后行断言和嵌套量词，避免规则导致导入任务失控。规则创建后先在预览中显示选中的路径、章节边界和最终页序，管理员确认后才生成草稿内容。

## 6. 目标导入流程

```text
私有存储频道上传 ZIP/CBZ
  -> Bot 登记 archive 入库项
  -> 管理台选择作品/内容单元和排序规则
  -> 创建 Import Job（待实现）
  -> Worker 受控下载到独立临时目录
  -> ZIP 结构预检、路径校验、图片扫描
  -> 应用排序规则，预览章节和页序
  -> 生成草稿章节、三版本图片和图片 Manifest
  -> 回传私有频道，记录新的 Telegram 文件 ID
  -> 管理员核验预览、设为 available、发布
```

压缩包如果没有目录层级，默认生成一个漫画章节；目录规则或 `chapter_page` 规则可生成多个章节。自动结果始终停留在草稿状态。

## 7. Comic Import Worker 准入要求

### 7.1 隔离与资源

- Worker 运行在独立容器或独立进程，不与 API/Bot Webhook 共用任务并发。
- 临时目录以任务 UUID 创建，任务终态后清理；目录应使用 `nodev,nosuid,noexec` 挂载选项。
- 初始并发为 1；队列使用 BullMQ，重复任务以源媒体 ID 去重。
- 任务需要记录源文件 SHA-256、大小、条目数、总解压大小、图片数、失败原因和耗时。

### 7.2 必须拒绝的输入

- 加密或需要密码的压缩包。
- 含绝对路径、`..` 路径、符号链接或无法规范化路径的条目。
- 超过单包大小、总解压大小、条目数、单图像素或压缩比阈值的任务。
- 不含支持图片、损坏、CRC 校验失败或无可用页面的包。

阈值在 Worker 环境变量中配置，并在作业记录中持久化当次使用值。下载适配器必须基于实际可获得文件大小选择云 Bot API、本地 Bot API 或 MTProto 获取链路；不能将视频的复制能力当作压缩包下载能力。

### 7.3 图片生成

每页生成并回传以下资源：

| 版本        | 用途           | 用户可见       |
| ----------- | -------------- | -------------- |
| `source`    | 管理与重新处理 | 否             |
| `browse`    | 漫画/图集阅读  | 是，受权限控制 |
| `thumbnail` | 列表与预读     | 是，受权限控制 |

同一页面三版本共用逻辑资源 ID；章节内 `browse` 页序从 0 开始且连续唯一。缺任一版本、图片尺寸不合规或回传失败都不得进入发布状态。

## 8. 分阶段计划

| 里程碑 | 范围                                         | 完成标准                                       |
| ------ | -------------------------------------------- | ---------------------------------------------- |
| M0     | 压缩包元数据、规则表、管理台规则页、发布保护 | 数据库迁移、契约测试和管理台构建通过。         |
| M1     | 真实 ZIP/CBZ 样本与下载边界验证              | 形成可复现样本、下载方式、容量阈值和失败记录。 |
| M2     | Import Job、受控预检和排序预览               | 可得到页面清单与章节草稿，不自动发布。         |
| M3     | 图像转换、Telegram 回传与 Manifest           | 合规包生成完整三版本，用户端能阅读。           |
| M4     | 压力、恢复、审计和灰度                       | 失败可重试/清理，生产监控和回滚流程通过。      |

### 8.1 M1 高容量内容准入档位

M1 对长篇漫画、写真和图集使用独立档位，不以普通图片作品的容量作为上限。以下数字是
当前 44 GiB 专用临时盘上的候选上限，必须在真实 Telegram 下载链路与目标 Worker 上实测
通过后，才可写入运行环境变量。

| 内容类型 | 单源压缩包 | 解压后图片总量 | 最大图片数 | 单图最大像素 | 单任务工作目录 |
| -------- | ---------- | -------------- | ---------- | ------------ | -------------- |
| 长篇漫画 | 4 GiB      | 24 GiB         | 15,000     | 64 MP        | 28 GiB         |
| 写真     | 4 GiB      | 24 GiB         | 8,000      | 80 MP        | 28 GiB         |
| 普通图集 | 3 GiB      | 18 GiB         | 5,000      | 64 MP        | 24 GiB         |

通用约束：单任务并发固定为 `1`；临时盘可用空间低于 `12 GiB` 时不取新任务；解压总量不得
超过源包的 `6:1`；单图片文件不得超过 `100 MiB`；三种派生版本逐页生成并回传，不能在临时盘
同时保留全量版本。加密包、路径穿越、绝对路径、符号链接、CRC 损坏包、无图片包和超过上述任一
上限的包必须在下载或解包早期拒绝。

## 9. 验收清单

1. ZIP 和 CBZ 在私有频道中分别被识别为 `archive`；普通文件不误判。
2. 未选择启用排序规则的压缩包不能关联入库。
3. 管理台可新增自定义规则，内置规则不可删除，已被导入源引用的自定义规则不可删除。
4. 排序预览对自然命名、数字序号、章节/页码和路径规则给出确定性结果。
5. 只有压缩包的漫画或图集单元不能发布，并显示明确原因。
6. Worker 拒绝恶意路径、加密包、压缩炸弹、损坏包和超限包。
7. 导入成功的每页均具有完整三版本、连续页序和正确权限范围。
8. 用户 API、Mini App、Bot 分发不暴露源压缩包、源图、临时路径、下载 URL 或 Telegram 文件 ID。
9. 任务失败后源压缩包仍可追溯，临时文件被清理，任务可从安全检查点重试。

## 10. 回滚

- 关闭 Import Job 消费者可立即停止新的压缩包转换，不影响已发布的标准图片章节。
- 保留 `archive_source` 与作业记录用于排障；不删除已生成的用户图片资源。
- 若某规则导致页序异常，禁用该规则、停止相关草稿的发布并使用另一规则重新生成预览。
- 数据库回滚仅在未有压缩包引用时删除规则表/字段；生产环境优先保留字段并关闭入口，避免破坏历史审计。
