# M1 验收记录：ZIP/CBZ 高容量内容与下载边界

## 1. 结论

验收状态：`BLOCKED`，M1 验收已启动但尚不可签发通过结论。

本地 M0 代码基线已经构建并通过自动化验证；生产实例仍运行 `0dd66f2` 发布版本，未包含
M0 的 `archive` 类型、排序规则表和管理接口。因此真实 Telegram ZIP/CBZ 入库测试当前会
得到假阴性，不能作为 M1 的结果。独立 Comic Import Worker、下载适配器、预检和图片转换也
属于后续里程碑，尚未实现，不能假定其能下载或处理多 GiB 压缩包。

## 2. 验收范围

- ZIP/CBZ 的识别、排序契约、管理端关联约束和发布保护。
- 长篇漫画、写真、普通图集的高容量准入阈值。
- Telegram 私有频道的源包下载边界。
- VPS 的临时盘、内存、服务隔离和根盘容量门槛。

不包含 Import Job、解压、图像转换、Telegram 回传和最终用户阅读链路。这些是 M2 及之后的
实现范围；M1 只冻结其进入实现前必须成立的输入、容量和下载前提。

## 3. 高容量准入档位

| 内容类型 | 单源压缩包 | 解压后图片总量 | 最大图片数 | 单图最大像素 | 单任务工作目录 |
| -------- | ---------- | -------------- | ---------- | ------------ | -------------- |
| 长篇漫画 | 4 GiB      | 24 GiB         | 15,000     | 64 MP        | 28 GiB         |
| 写真     | 4 GiB      | 24 GiB         | 8,000      | 80 MP        | 28 GiB         |
| 普通图集 | 3 GiB      | 18 GiB         | 5,000      | 64 MP        | 24 GiB         |

通用限制：

- Worker 并发固定为 `1`，一个任务独占临时盘配额。
- 取得任务前，专用临时盘必须至少保留 `12 GiB` 可用空间。
- 源包与解压后内容的最大压缩比为 `6:1`。
- 单图片文件最大 `100 MiB`；图片仅按页处理，派生的 `source`、`browse`、`thumbnail` 不能全量
  并存在临时盘。
- 拒绝加密包、CRC 损坏包、无图片包、绝对路径、`..` 路径、符号链接和超过任一容量或像素阈值
  的条目。

这些上限在当前专用盘可用约 `41 GiB` 的条件下预留了 `12 GiB` 水位，最大工作目录为 `28 GiB`。
它们是待实测的候选值，尚未写入应用环境变量，也不会在当前未实现的 Worker 上生效。

## 5. 已验证证据

### 5.1 本地 M0 基线

2026-09-05 在工作区代码基线 `5eb56b1` 加本地 M0 未提交改动上执行：

```text
pnpm test       exit 0  (39 tests passed)
pnpm typecheck  exit 0
pnpm build      exit 0
```

其中包含：ZIP/CBZ 识别、数字与章节页码排序、压缩包只能作为受保护源资源、非压缩包不能关联排序
规则，以及仅有压缩包的图片内容单元不能发布。

### 5.2 VPS 容量与隔离

2026-09-05 只读检查结果：

```text
CPU / RAM              2 vCPU / 4 GiB
临时盘                /var/lib/vidpic-epub-tmp
临时盘大小 / 可用空间  44 GiB / 约 41 GiB
挂载选项               rw,nosuid,nodev,noexec,relatime
根盘大小 / 可用空间    5.4 GiB / 约 879 MiB
```

专用盘的挂载选项与候选阈值相容；路径名称仍沿用历史名称，实际启用 Worker 前应改为
`/var/lib/vidpic-archive-tmp`。根盘余量不满足发布、日志增长和故障转储的最低余量要求，必须在
高容量验收前处理。

### 5.3 生产实例一致性

生产 API 与 Bot Worker 的正确健康地址返回 `200`，依赖检查均为 `ok`。但生产实例运行的是
`/opt/vidpic-hub-bot/releases/20260904-0dd66f2`，且：

```text
GET /api/admin/archive-sort-rules -> 404 NOT_FOUND
```

这证明 M0 的规则接口尚未部署到验收实例。当前生产版本不能用于 ZIP/CBZ 入库的真实环境验收。

## 7. M1 签发条件

仅当 B-01 至 B-05 全部关闭，并且三类正向边界样本均在真实 Telegram 链路中成功完成“下载到受控临时
目录”步骤，四类负向样本均在完整解压前被拒绝，才可将 M1 标记为 `PASS` 并进入 M2。任何一个
高容量样本造成 API/Bot Worker 就绪探针失败、临时盘低于 12 GiB 水位或泄露源包信息，均保持
`BLOCKED`，不得进入后续导入实现。
